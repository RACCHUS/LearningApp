### 1.3 — Focus mode for study screens
**Why:** Cognitive load theory — hide extraneous UI during study.

**Implementation:** Add a `focusMode` state to study screens. When active:
- Hide bottom nav bar (already uses `GoRouter` shell — conditionally hide)
- Collapse AppBar to a minimal top bar (progress only)
- Tap card area or swipe down to briefly show controls

**Files to change:**
- `lib/screens/study/flashcard_screen.dart` — wrap AppBar in conditional, add `SystemChrome.setEnabledSystemUIMode`
- `lib/screens/study/mcq_screen.dart` — same
- `lib/screens/study/lesson_content_pager.dart` — same
- `lib/components/main_scaffold.dart` (or equivalent shell) — hide bottom nav during study routes

**Effort:** ~3 hours. Non-breaking — focus mode is opt-in.

---

### 1.4 — Batch size control
**Why:** Cognitive load — prevent overwhelm by capping cards per session.

**Implementation:** Add `studyBatchSize` to settings (default 15). Study screens slice their content list to `min(content.length, batchSize)`.

**Files to change:**
- `lib/models/settings.dart` (or equivalent) — add `studyBatchSize` field (default: 15)
- `lib/screens/study/flashcard_screen.dart` — apply batch limit before building PageView
- `lib/screens/study/mcq_screen.dart` — same
- `lib/screens/study/lesson_screen.dart` — show "Session complete! X cards remaining for next time." when batch ends

**Effort:** ~2 hours.

## Sprint 2: Study Science Features

### 2.1 — Break/Pomodoro system
**Why:** Research shows structured breaks improve focus and retention.

**Implementation:** Extend existing `TimerProvider` with break awareness:
- After timer expires → show full-screen break overlay with countdown (5 min)
- After 4 work blocks → suggest longer break (20 min)
- Track total study time in session

**Files to change:**
- `lib/providers/timer_provider.dart` — add `breakDuration`, `blocksCompleted`, `isOnBreak` state, auto-transition logic
- `lib/widgets/timer_widget.dart` — update UI for break state
- `lib/widgets/study/break_overlay.dart` — **new file**: full-screen break prompt ("Nice work! Take a 5-minute break.")
- `lib/screens/study/flashcard_screen.dart` — integrate timer + break overlay
- `lib/screens/study/mcq_screen.dart` — same

**Effort:** ~4 hours. Timer exists; main work is break overlay + integration into study screens.

---

### 2.2 — Recall before reveal (flashcards)
**Why:** Testing effect — active retrieval >> passive re-reading.

**Implementation:** Before showing the answer on flashcard back:
- Show prompt: "Think of the answer, then tap to reveal"
- Add "I recalled it" / "I didn't know" buttons after reveal (maps to SM-2 quality rating)
- Remove auto-flip or passive swipe-to-next

**Files to change:**
- `lib/widgets/study/flashcard_content.dart` — add intermediate "recall prompt" state between front and back
- `lib/screens/study/flashcard_screen.dart` — add self-rating buttons after reveal

**Effort:** ~3 hours.

---

### 2.3 — Quick Review mode (auto-interleaved)
**Why:** Interleaving + microlearning — cross-lesson review with no setup required.

**Implementation:** New "Quick Review" button on home screen:
- Pulls N due items from `SpacedRepetitionService` across all lessons
- Falls back to random items if nothing is due
- Uses existing `MixedModeScreen` but with cross-lesson content

**Files to change:**
- `lib/screens/home_screen.dart` — add "Quick Review" action card
- `lib/providers/quick_review_provider.dart` — **new file**: gather due items cross-lesson, limit to batch size
- `lib/screens/study/mixed_mode_screen.dart` — accept external content list (may already support this)

**Effort:** ~3 hours. Leverages existing spaced repetition + mixed mode infrastructure.

---

### 2.4 — Granular lesson progress
**Why:** Zeigarnik effect — visible incompleteness drives completion.

**Implementation:** Replace 3-state progress (0%/50%/100%) with actual mastery percentage:
- Track per-term and per-MCQ mastery (passed ≥1 review = mastered)
- Display as percentage on lesson cards: "Variables: 73% mastered"
- Optional: replace accent stripe with a small circular progress indicator

**Files to change:**
- `lib/providers/lesson_progress_provider.dart` — compute granular percentage from SM-2 item states
- `lib/widgets/lesson_card.dart` — display mastery percentage, optionally use `CircularPercentIndicator`
- `lib/models/lesson_progress.dart` — add `masteryPercentage` computed field

**Effort:** ~4 hours. Depends on how SM-2 item data is stored/queried.

## Key Principles During Implementation

1. **Everything is nullable/opt-in** — emoji, focus mode, batch size. No breaking changes to existing data.
2. **No paid APIs required** — emoji are text, colors are theme tokens, all features work offline.
3. **Test the science features** — timer, batch size, and recall-before-reveal change study behavior. Write tests for these.
4. **Don't over-animate** — respect `MediaQuery.disableAnimations`. Keep transitions ≤300ms.
5. **Generation prompts are cheap to update** — any schema addition (emoji field) must also update the AI prompts.
